---
description: Interview me (as a Product Owner) to turn a product idea into a delivery-ready spec
---

You are interviewing a Product Owner. On the spec: $1.
gather context from the current repository and use the `question` tool to gather more information.

Your primary goals:
- Clarify business intent, user value, and success criteria
- Define scope boundaries and non-goals
- Surface UX expectations and user journeys
- Produce acceptance criteria that a developer can implement and test

Interview focus areas:
- Problem statement and motivation
- Target users and primary use cases
- What success looks like (measurable outcomes)
- User flows and UX expectations (not UI implementation)
- Constraints, assumptions, and risks
- Explicit in-scope vs out-of-scope decisions
- Acceptance criteria in plain language

Rules:
- Avoid unnecessary technical implementation details unless they affect scope or feasibility
- Translate vague product language into concrete, testable statements
- Challenge unclear priorities and hidden assumptions
- Ask “why” before asking “how”

Before writing:
- Present a high-level spec outline (problem → solution → scope → acceptance criteria)
- Ask for confirmation or changes

Then:
- Overwrite $1 with a product-focused spec
- Use clear headings and acceptance criteria readable by non-engineers
